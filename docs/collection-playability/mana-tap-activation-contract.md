# Proposed semantic contract: mana plus tap to draw

Status: design proposal, not implemented. This contract is limited to mechanical evidence for a single activated draw ability. It is not a Phase 2 efficiency verdict, strategic finding or game-state simulator. The Phase 2 guide (sections 5.3 and 11) requires a broader efficiency model.

## Sources and existing behavior

The pinned Jayemdae Tome record in `tests/fixtures/cpa_repeatable_draw.json` has Oracle ID `39ee576a-0803-4063-9c84-f2b537e4d44c` and source `{4}, {T}: Draw a card.`; the fixture identifies the Scryfall snapshot and checksum. The [official Comprehensive Rules effective 2026-11-06](https://media.wizards.com/2026/downloads/MagicCompRules%2020261106.txt) define activated ability costs and instructions in 602.1 and 602.1b, tapping in 107.5, creature restrictions in 302.6/602.5a, and the haste exception in 702.10c. These rules also make clear that a restriction after the effect can govern activation rather than being an effect. The fixed source snapshot and rules version are distinct provenance.

The boundary resolver currently stores the complete trimmed pre-colon string and the containing Oracle span, card, face and boundary identity. `ExecutionUnit.activation_cost` carries the string, and `MechanicalUse` links an execution unit, evidence and qualitative requirements; the original span identifies the full boundary, but a separately indexed cost-only evidence span and structured mana components are not currently guaranteed. The native mechanical capability can record its costs, subject to extraction limits. The verifier's `_COST` accepts a contiguous sequence of symbols but no comma or whitespace, so `{4}, {T}` fails that check. Draw still requires matching native facts and no unresolved relevant warning. The mechanical adapter also checks execution identity, unknown spans, target uncertainty and card dependencies. Merely changing the regex cannot guarantee a supported use or safe strategy evidence.

The older ability-boundaries decision says the execution adapter does not consume boundaries, whereas current `mechanics.py` does. This is a documentation/code divergence; current code is the implementation source of truth. Further, the repeatable-draw test explicitly expects Jayemdae Tome to remain unsupported; changing that behavior requires updating that specific expected assertion with independent justification, while retaining all negative assertions. No test is changed in this design round.

## Proposed acceptance contract

For a resolved, unambiguous activated boundary on a known card and face, require the *entire* source to match this restricted grammar after removing only outer boundary whitespace:

```
MANA  := one or more contiguous symbols {n} or {W} {U} {B} {R} {G} {C}
COST  := MANA, followed by a comma, zero or more spaces/tabs, and exactly {T}
BODY  := Draw a card. | Draw one card. | Draw two cards. | ... | Draw five cards. | Draw <decimal> cards.
ABILITY := COST: BODY
```

Here `{n}` is a non-negative decimal generic mana symbol; uppercase symbols and conventional punctuation are required. The existing allowlist accepts `a`, `one` to `five` and decimal quantities; require the grammatical singular/plural form or explicitly test and document any existing permissiveness rather than treating invented text as Oracle. Whitespace after comma and after colon can vary between zero and spaces/tabs if the resolver and native evidence still independently identify the complete unit. Newlines, reversed cost order, hybrid, Phyrexian, snow `{S}`, variable `{X}`, untap `{Q}`, more than one tap symbol, text costs and additional clauses are outside this proposal. This is a deliberately narrower grammar than Magic's full syntax and than the verifier's present generic symbol pattern: it makes no claim that excluded text is illegal. Even eligible syntax must have a supported native draw fact, source-aligned evidence and no unresolved native warning.

For a successful local interpretation:

1. Preserve the exact original full activation-cost string, including spacing and punctuation; retain an exact source span into the pinned Oracle snapshot (either an explicitly validated cost-only span or a verifiable derivation from the complete boundary and colon). Never reconstruct the cost by formatting parsed tokens. Record the boundary's original full span and draw evidence.
2. Bind card ID, face index, boundary ID, execution-unit ID and draw evidence together; evidence must be contained within the uniquely resolved boundary and match the original text. A boundary shared by multiple effects or crossing evidence is not independently verified unless the existing boundary-scoped extraction has proved the association. Never equate a parser paragraph ID with a boundary ID.
3. Expose distinct conditional prerequisites `pay_ability_cost` for the exact mana symbols and `tap_source` for each activation. The mana symbols remain separately inspectable via the exact cost and, if a structured representation is added, it must retain each symbol without a common resource score. Do not interpret printed casting cost as activation cost.
4. A further activation needs priority/permission, a source capable of tapping again, and all costs payable again. No assumed untap source, fixed per-turn frequency or unlimited repeatability. The source must be a permanent capable of paying `{T}`. Runtime type/control history is not modeled; if it is a creature, the continuous-control rule applies unless an applicable exception such as haste is established. Printed noncreature type does not prove it cannot become a creature. External effects, timing, ownership/control and state may prevent activation or change costs. State-dependent feasibility remains conditional or unknown.
5. Successful source interpretation is only evidence of the printed activation. Require Phase 1's dependency, boundary, native warning, target and execution checks to remain intact. Any unresolved relevant dependency, linked effect, ambiguous face/unit, unmodeled cost or activation instruction requires unknown/unsupported, with reasons and evidence retained. Conditional restrictions cannot be silently discarded. An independent supported keyword or separate ability is not presumed irrelevant unless the existing dependency gate establishes that within its documented scope.
6. A verified local boundary and conditional mechanical use do not establish net card value, whole-card completeness, legal activation in a particular game, strategic synergy, or eligibility for the fixed-draw sorcery efficiency comparator. Unsupported uses must never yield positive strategy evidence.

A proposed representation should reuse `BoundaryCoverage`, `ExecutionUnit` and `MechanicalUse`. A separately typed mana-cost field or cost-span field requires a contract/versioning decision; until then the source substring is the authority. If no exact source mapping or symbol-to-cost association can be verified, abstain. Do not add a duplicate native parser or modify native evaluators for this scoped change.

## Independent acceptance examples

| Source / variant | Expected contract result |
| --- | --- |
| Jayemdae Tome `{4}, {T}: Draw a card.` | Positive candidate only if native draw evidence, exact boundary association, unknown-warning and dependency checks pass. `pay_ability_cost` and `tap_source` apply for every activation. |
| Synthetic `{2}{U}, {T}: Draw a card.` or `{2}{U},{T}: Draw a card.` | Same semantics if and only if the actual resolver and native extractor can substantiate each spelling; preserve the distinct source text. If native extraction fails, abstain. |
| Change `{4}` to `{5}` | Preserve changed exact cost and changed evidence/identity; never reuse old cost or cached profile. No comparative efficiency conclusion follows. |
| `{B}, Pay 2 life: Draw a card.`; `{1}, {T}, Sacrifice this artifact: Draw a card.`; discard or remove-counter costs | Outside contract; preserve all source text and abstain. Greed, Mind Stone and Tome of Legends provide pinned cases. |
| Arch of Orazca: `{5}, {T}: Draw a card. Activate only if you have the city's blessing.` | Extra activation instruction and other boundaries must not be dropped; abstain pending supported condition/dependency modeling. |
| Jalum Tome: `{2}, {T}: Draw a card, then discard a card.` | Draw and discard are one resolution; discard is an effect, not an activation cost. This contract does not verify the bundle. |
| Two independent abilities in one paragraph, including a candidate | Verify a candidate only if boundary partition and any crossing evidence are resolved by the existing scoped extraction, with independent dependency assessment. Otherwise abstain; never transfer a cost to the other ability. |
| Candidate plus `Activate only as a sorcery` or a separate restricting static ability | Do not promote while the instruction or dependency is unmodeled; retain the restriction and uncertainty. |
| Quoted, modal, linked or cross-face ambiguous text | Abstain unless existing scoped evidence and dependency rules independently establish the full association; no blanket multi-face support is assumed. |

## Proposed implementation and validation after approval

Likely files: `src/mana_architect/collection_playability/semantic_coverage.py` for a tightly scoped matcher and verifier version; `src/mana_architect/collection_playability/mechanics.py` for separately propagated prerequisites if existing propagation is insufficient; `src/mana_architect/collection_playability/contracts.py` only if an explicit source-bound cost representation is justified; targeted tests in `tests/test_collection_playability_semantic_coverage.py`, `tests/test_collection_playability_mechanics.py`, `tests/test_collection_playability_dependencies.py` and `tests/test_collection_playability_repeatable_draw.py`, plus this decision note. Preserve `ability_boundaries.py`, native engines and the efficiency comparator unless a concrete blocking defect independently justifies a separately reviewed change. Investigate actual scoped extraction and warning behavior before selecting the minimal edit.

Test exact original spans and cost text, correct card/face/boundary/unit, conditional per-activation mana and tap, rules-dependent creature/haste uncertainty, repeated and reversed-order determinism, cost mutation and added restrictions, semantic-equivalent formatting only when native evidence is available, multiple same-paragraph abilities, ambiguous and cross-face examples, and all life/sacrifice/discard/counter and linked-effect abstentions. Keep the previous real-card and fixed-draw Golden cases including peer truncation; update only the Jayemdae-specific Phase 1 expectation if independent acceptance actually succeeds, never erase the remaining negative expectations. Run CPA contracts, adapter, boundary, semantic-coverage, dependency, mechanical and efficiency tests plus upstream and applicable full-suite regressions. Report Streamlit AppTests separately.

Any implementation changes Phase 1 semantic coverage, applicability, safety, strategy eligibility and content-derived profile IDs even if native engine versions and source evidence IDs remain unchanged. Version the verifier and any changed serialized contract/cache key, document compatibility and invalidate or regenerate affected persisted CPA profiles. Native engines and already published pairwise artifacts need not be regenerated solely for CPA-local changes, provided their native versions and evidence remain unchanged; if native extractors change, reassess their published-artifact compatibility. No comparator expansion or production change is authorized by this note.
